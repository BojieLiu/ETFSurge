## 1. 子项清单（按风险档次单调 + 核心层 beta 上限）

### E1（#10）核心层 beta/波动率上限
- **问题**：`allocation_engine` 把创业板/科创50 当宽基核心按因子分选入 core，核心层无 beta/波动率上限 → 平衡型核心 67% 高 beta 成长（design 534 实测）。
- **修复**：core 层加「高 beta 资产（创业板/科创50/恒生科技等，由 `etf_classifier` 标签或历史波动率判定）合计权重 ≤ X%」（建议 X=40%，待探针定）。超出部分在 core 层内做等权降级，腾出的权重回流 satellite/CASH。
- **证据链**：design 534 `strategies_json` 实算 创业板0.1001+科创50 0.0999 = 核心 67%；`allocation_engine.py` core 选择段（`_select_core` 附近，需定位具体行）。
- **验收（负向）**：`平衡型 core 高 beta 占比 > X% → FAIL`；`assert 核心层 beta 加权平均 ≤ 组合中位 beta×K`。
- **复杂度审计**：纯计算，无 I/O；需在 core 选择后新增一段约束回写。
- **探针 D1**：现有 26 标的 240 根 K 线是否够算 beta/历史波动率（相关矩阵缓存 `_CORR_CLOSES_CACHE` 已有，可复用）。

### E2（#11）卫星数量随风险档次单调递增
- **问题**：卫星数 防御 2 / 平衡 6 / 进攻 2 倒挂；进攻型卫星反而最少。
- **修复**：卫星数量下限随 `risk_profile` 单调递增——防御 ≥2、平衡 ≥4、进攻 ≥6（具体上界待定）。解开进攻型卫星卡 2 的上限（`allocation_engine.py` satellite 选择段，与 P2-6 方案A 同函数）。
- **验收（负向）**：`卫星数：进攻 < 平衡` 或 `进攻 < 2` → FAIL（回归 round12 `test_satellite_min_count` 保底 ≥2 语义）。
- **复杂度审计**：纯计算，改 satellite 选择循环的下限常量/分支。

### E3（#12）标的总数随风险档次单调递增
- **问题**：总标的数 防御 10 / 平衡 13 / 进攻 8 倒挂（进攻比防御还少）。根因同 E2（卫星卡 2）+ 进攻核心仅 3 只。
- **修复**：核心 + 卫星选择随风险档次放大，保证 `进攻型标的数 ≥ 防御型`。核心层下限：防御 ≥3、平衡 ≥4、进攻 ≥5（待探针定）。
- **验收（负向）**：`进攻型标的数 < 防御型` → FAIL。
- **复杂度审计**：与 E2 同段，一并改。

### E4（#13）进攻型层结构去保守化
- **问题**：进攻型 防御层 19%（国债5.1%+黄金5.1%+地债8.7%）+ 现金 25% = 44% 非权益压舱，对「进攻」偏保守。
- **修复**：进攻型防御层压到最低（仅黄金 ~5%）；现金 `<10%`；腾出权重让给核心 + 卫星。与 E2/E3 协同（卫星放大自然吃掉现金）。
- **验收（负向）**：`进攻型 非权益压舱（防御层+现金）> 30%` → FAIL；`进攻型现金 > 20%` → FAIL（round21 原 ⚠️ 仅预警，本次强约束）。
- **复杂度审计**：纯计算。

### E5（P1-1 设计路径收口）相关性约束在交易时段复测
- **问题**：实证显示设计路径 `enforce_max_correlation` 已实现，但 design 534 无 `correlation_warnings`——疑似非交易窗口 `corr_matrix` 空被跳（`strategy_design.py:398` `if corr_matrix:`）。
- **修复**：非交易/数据缺失时，相关性约束**不得静默跳过**——降级为 `risk_metrics.correlation_unchecked=True` 显式标注（前端提示「关联度未校验」），而非假装已校验。不阻塞主链路。
- **验收**：非交易窗口 design → `risk_metrics.correlation_unchecked=True` 断言；交易时段 design → 高相关对合计权重 ≤0.25 断言。
- **验证窗口**：**交易日 9:30-11:30/13:00-15:00 + 真实环境**（依赖实时 K 线相关性矩阵）。
- **复杂度审计**：无新 I/O；仅改跳过分支的降级标注。
