# 审阅报告：ETF Surge 各链路产出质量分析

## 1. 市场状态判定链路 — 设计 vs 策略检查

**发现问题：两个管线的市场状态判定不一致**

| 管线 | 判定 | 来源 |
|------|------|------|
| 组合设计 | `correction`（回调期）| pool_manager.get_market_regime() |
| 策略检查 | `range_bound`（震荡市）| compute_etf_trends() → fetch_index_realtime() |

**分析**：这两个判定来自不同数据管道。设计引擎走 `pool_manager`（综合因子+趋势+新闻），策略检查走独立的 `market_trends.detect_market_regime()`（偏技术面）。不同管线产出一致性判定是合理的——correction 和 range_bound 有重叠区域。建议在策略检查中复用 pool_manager 的 regime 判定。

**评分**：3/5 — 存在不一致但都可接受

## 2. 组合设计链路 — 逻辑自洽性

### 2.1 宏观逻辑流：数据 → 判断 → 行为

```
情绪指数: 30/100 (谨慎)
技术面: 沪深300 -3.5%, 20日均线下方-6.4%
   ↓
市场状态: correction
   ↓
三层预算:
  防御型: core 45% / sat 10% / def 15% / cash 30%
  平衡型: core 47% / sat 18% / def 13% / cash 22%
  进攻型: core 51% / sat 25% / def 10% / cash 15%
   ↓
现金: 14.8%~30% (偏高, 符合correction)
防御层: 10%~15% (包含黄金+国债, 合理)
```

**逻辑链完整自洽**。correction 状态下现金偏高、防御层扩大，三层之间的梯度（防御→平衡→进攻）连续平滑。

**评分**：5/5

### 2.2 三层方案梯度

- 防御型: 卫星层9%（3只行业ETF），防御15%（黄金+国债），现金30%
- 平衡型: 卫星层最低...wait, 平衡型9只中只有半导体+AI+新能源+医药=17%，比防御型的9%更多
- 进攻型: 卫星层更多（+旅游+军工），现金15%

**√ 梯度清晰**。从防御→平衡→进攻，卫星层权重递增，防御层递减，现金递减。

**评分**：4/5 — 层次分明，但可增加梯度对比表

### 2.3 个股入选理由

```
510300 沪深300: "今日跌3.5%；沪深300ETF — A股核心宽基...近3月跌3.7%；近1月跌7.9%"
518880 黄金ETF: "今日跌0.6%；黄金ETF — 贵金属避险资产...近3月跌17.2%"
512480 半导体: "今日跌7.7%；近3月跌35.3%；近1月跌56.9%"
```

**评分**：4.5/5 — 数据详实、前后一致，每条理由包含当日涨跌幅+趋势+技术面+层角色+市场状态

## 3. 投资判断准确性

### 做对的判断
| 判断 | 是否正确 | 依据 |
|------|---------|------|
| correction + 高现金 | ✅ | 回调期控制仓位是标准做法 |
| 红利低波作核心层 | ✅ | 防御性板块波动小，适合底仓 |
| 黄金作为防御层 | ✅ | 正常应看涨，但系统诚实注明了"强美元压制" |
| 合并重复ETF | ✅ | A500/红利ETF多份额，市场确实如此 |

### 值得商榷的判断
| 判断 | 问题 | 建议 |
|------|------|------|
| 半导体ETF-56.9%仍入选 | 跌幅巨大，短期风险极高 | 卫星层权重应更小（<2%）或设跌幅阈值自动排除 |
| 旅游ETF无行情数据 | 数据采集中断，无涨跌幅 | 候选池应有cleanup机制剔除无数据标的 |
| 黄金ETF -17.2%在防御层 | 黄金跌幅大于权益，防御功能失效 | 应设"防御资产有效性"检查 |

## 4. 语言质量与AI味检查

### 正面
- 数值嵌入自然："今日跌3.5%；近3月跌3.7%"
- 情景解释不突兀："宏观弱复苏·宽松；市场情绪偏谨慎"
- 黄金 ETF 的矛盾解释写出："受强美元+高利率压制，短期避险功能受限但长期配置价值仍在"——这个表述自然、不像模板

### 问题
- 模板化结构过一致：每条理由都按"当日涨跌 → 资产介绍 → 趋势 → 技术面 → 市场状态 → 层角色"排列，读多了显刻板
- 部分句式固定："在XX方案中作为XX" 出现频次过高

**评分**：3.5/5 — 数据详实但模板感可以进一步淡化

## 5. 数据完整性检查

| 数据字段 | 覆盖率 | 缺失情况 |
|---------|--------|---------|
| 当日涨跌幅 | ~90% | 旅游ETF、军工ETF无当日数据 |
| 近3月涨跌幅 | ~85% | 旅游、军工无趋势数据 |
| 近1月涨跌幅 | ~85% | 同上 |
| 均线偏离率 | ~70% | 部分ETF无MA数据 |
| 资金流向 | ~50% | 部分ETF无主力资金数据 |

**评分**：3/5 — 数据管道覆盖了大部分ETF，但仍有部分标的遗漏，应链入更多数据源

## 6. 关键改进建议

1. **统一市场状态判断** — 让策略检查复用 pool_manager 的 regime
2. **自动排除极端下跌标的** — 月跌幅>40%的 ETF 自动阈值过滤
3. **防御资产有效性检查** — 黄金在周期内若跌幅>10%，降低其防御角色权重
4. **候选池 freshness 检查** — 对缺失行情数据的标的做过滤标记
5. **语言多样化** — 层角色模板随机选一，减少 AI 模板感
